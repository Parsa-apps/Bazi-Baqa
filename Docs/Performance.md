## چه چیزی واقعاً هزینه را کم می‌کند؟

| سازوکار | کجا | اثر |
|---|---|---|
| یک متریالِ کش‌شده برای هر (سبک، تینت، تنظیم) | `MaterialLibrary` | draw call و set-pass‌ها؛ تستِ کش در `GraphicsPerfPlayModeTests` (۲۰۰ درخواست = ۱ متریال) |
| چمن در یک مشِ واحد | `FoliageScatter` | ۲۲۰..۱۷۰۰ بوته = ۱ draw call، بدونِ ShadowCasting |
| کالینگِ فاصله/حجمِ دید | `DistanceCuller` | رندر و «سایه‌ریختن» اجزایِ دور صفر می‌شود |
| استخرِ اجزایِ افکت | `VfxDirector` | هیچ `Instantiate` در هر انفجار/برخورد نیست (سقف = ظرفیتِ استخر) |
| جاروبِ شیشه با یک بردارِ سراسری | `UIGlassPanel` | ۴۰ پنل، یک متریال، یک `SetVector` در فریم |
| باد در شیدر (یک بردارِ جهانی) | `WindField` | صفر CPU در هر شیء؛ با ضریبِ هر سطح (`windScale`) |
| `particleRaycastBudget` + `asyncUpload*` | `RenderPipelineBridge` | برخوردِ باران با صدها collider و پرشِ بارگذاریِ بافت کنترل می‌شود |
| `QualitySettings` فقط در یک فایل | `RenderPipelineBridge` | دو مؤلفه با هم می‌جنگیدند؛ حالا گزارشِ یک‌خطی داریم |
| کاهشِ خودکارِ کیفیت با FPS | `PerformanceManager` (Gameplay، دست‌نخورده) | زیرِ ۳۰ فریم یک سطح پایین؛ `GraphicsDirector` همان تغییرِ سطح را به همه‌ی لایه‌هایِ بصری اطلاع می‌دهد |

### چرا Occlusion Culling بیک‌شده نه؟
`Occlusion Culling` یونیتی داده‌اش را از اشیای *صحنه* در ادیتور می‌سازد؛ زمینِ «سرزمین بقا»
در زمانِ اجرا با `WorldGenerator` تولید می‌شود، پس هیچ دیتایِ بیک‌شده‌ای برایش معنا ندارد.
یونیتی خودش frustum-culling را انجام می‌دهد؛ کاری که ما اضافه می‌کنم آن است: **قطعِ
سایه‌افکنی** و **خاموش‌کردنِ رندرِ اجزایِ آن‌سویِ فاصله** (که یونیتی برای مش‌هایِ کوچکِ
پراکنده انجام نمی‌دهد) ⇒ تستِ دیدِ لمسی و منطقِ بازی هیچ‌وقت درگیر نمی‌شوند چون کالر فقط
`Renderer.enabled`/`shadowCastingMode` را لمس می‌کند.

### چرا `CullingGroup` نه؟
`CullingGroup` برای مجموعه‌هایِ ایستا طراحی شده و باید آرایه‌ی موقعیت/شعاع را هر بار که
بازمانده‌ها جابه‌جا می‌شوند دوباره بدهیم (۴۸ نفره ⇒ هر فریم). مسیرِ ما: یک پاسِ ۴ هرتزی روی
حداکثر ۹۶..۳۲۰ هدف، با بافرِ بازاستفاده‌شده ⇒ رفتارِ قابل‌ پیش‌بینی، GC صفر، و تست‌پذیر ✓.

## چگونه اندازه بگیریم؟
1. `Window → Analysis → Profiler` (Deep Profile خاموش) + `Rendering → Frame Debugger`.
   در Frame Debugger باید اینها دیده شوند: یک draw برای زمین، یک draw برای چمن،
   یک draw برای کل UIِ پنل‌ها (شیشه‌ای، چون متریال مشترک است).
2. در `Console` خطِ `GraphicsDirector | …` را ببینید:
   `pipeline=… | volume=… | materials=N | sky … | wind … | foliage tufts=… draw=1 | vfx active=… | motion actors=… | cull targets=… full=… hidden=…`
   عددِ `materials` باید پس از چند بازسازیِ جهان ثابت بماند (نشتیِ متریال = باگ).
3. `python3 Tools/procedural_textures.py --check` — حجمِ بافت‌هایِ منبع (۱۰ دانه ۲۵۶×۲۵۶ و
   ۵ دانه ۱۲۸×۱۲۸، در مجموع ≈ ۰٫۹ مگابایت؛
   با ASTC + mip در APK حدودِ ۱ مگابایت).
4. `bash Tools/unity_validation.sh` رویِ ماشینِ دارایِ Unity (import + compile + test runner).

## چک‌لیستِ آزمونِ نهایی (بخش ۱۰ خواسته‌ها)
دستِ شما، رویِ دستگاهِ هدف — هیچ‌کدام از اینها نباید با گرافیکِ تازه بشکند:

| مرحله | باید چه بشود؟ |
|---|---|
| باز شدنِ بازی | اینتروی استودیو ۲٫۶ ثانیه، بعدِ آن کلیکِ «شروع» همان لحظه کار می‌کند |
| منوی اصلی | پنجره‌ها یکی‌یکی با محوشدگی باز می‌شوند؛ متن‌ها ۱۰۰٪ فارسی و راست‌به‌چپ |
| شروعِ بازی | دوربینِ ایزومتریک، مه/باد/نورِ صبح؛ FPS رویِ low ≥ ۴۵ |
| ساختِ ساختمان | پنلِ ساخت شیشه‌ای + ریپلِ دکمه؛ ساختمان با رشدِ مقیاس از زمین بلند می‌شود |
| ارتقا | پالسِ کوتاه و کمی بزرگ‌ترشدنِ ریشه (توسطِ منطق، نه انیماتور) |
| حمله/آسیب | اندام‌ها تکانه می‌دهند، بدن له می‌شود، دوده رویِ ساختمان می‌نشیند |
| چرخه‌ی شب | آسمانِ رویه‌ای، چراغ‌ها تا سقفِ بودجه، مه کم‌رنگ‌تر؛ سایه‌ها کوتاه می‌شوند |
| باران/طوفان | ذراتِ باران، کف رویِ آب، `particleRaycastBudget` نباید FPS را بشکند |
| انفجار/آتش | بدونِ Frame spike (استخر؛ `vfx active=` هیچ‌وقت از سقف نمی‌گذرد) |
| پنل‌هایِ دور از دید | در Frame Debugger نباید رندر شوند (`cull … hidden=N`) |
| کیفیت‌هایِ چهارگانه | هر بار تغییرِ کیفیت: `RenderPipelineBridge` یک‌بار اعمال می‌کند (نه هر فریم) |
| خروجی Android | `BaziBaqa/Build/Android` + جدولِ نسخه (`Docs/AndroidBuild.md`) |

### اگر چیزی شکست
- «پنل‌ها تخت‌اند»: شیدرِ UI حل نشده؛ `UIGlassPanel.Report()` → `shader=off` ✓ مسیرِ پشتیبان.
- «چیزی ناپدید شده»: کالر را با `GraphicsDirector.Instance.Cull.Report()` چک کن؛ اگر
  `hidden` زیاد است، `cullDistance` همان سطح را در JSON بالا ببر (تغییرِ بصری، بدونِ منطق).
- «FPS افت می‌کند ولی کیفیت پایین نرفته»: `PerformanceManager` را در لاگ ببین
  (`log.quality_down`); کلیدِ بومی‌سازی‌اش هست و صحنه‌هایِ تست آن را نادیده می‌گیرند.
